# План строительства RusCraft (blueprint)

**Цель:** RusCraft — полностью веб-игра на основе открытого кода Luanti (ex-Minetest),
русский интерфейс, максимально близкая к оригиналу. Без собственной бэкенд-разработки:
статическая выкладка + опциональный WSS-прокси.

**Точка входа для холодного агента:** прочитай `docs/RESEARCH.md` (факты, версии, флаги),
затем выполни шаг из очереди ниже. Шаги самоcontained: контекст каждого — в его брифе.

**Текущий статус (2026-11-18, вечер):**
- Решения человека: игра = Minetest Game, сборка = GitHub Actions, прокси = self-hosted
  lwproxy на VPS, хостинг = свой VPS.
- S0 ✅, S1 ✅ (полный зелёный прогон run 44256312644 за 16м08с; артефакт 21 МБ в www/,
  uuid релиза 5d7c741bbe32; починки по пути: Node 24 в образе, статический zstd —
  см. журнал), S3 🔶 (RU-оболочка работает в браузере; осталось: favicon, мелочи),
  S4 🔶 (пак minetest_game автоустанавливается без ContentDB — проверено в браузере;
  офлайн-поведение всего меню — на ручной проигровке).
- S2 ✅ автоматическая часть: crossOriginIsolated=true, wasm+OPFS ("backed by OPFS"),
  паки base/certs/minetest_game установлены, рестарт страницы → "Pack base is already
  installed", игра стартует (--gameid minetest_game, language=ru, offscreen WebGL2-
  канвас живёт в pthread). Скриншоты: shots/s2_after_play.png.
- S2 ручной гейт (человек): провдить мышью в окне Chrome, создать мир, убедиться в
  сохранении. Дальше — S5 (внутриигровой бренд/текстуры), S6 (lwproxy на VPS — нужен
  доступ к VPS и домену), S7 (выкладка на VPS по deploy/nginx.conf).

**Режим работы:** direct (git-репозиторий локальный; удалённый GitHub появится после
решения Q-B — тогда добавим ветки/PR).

### S0. Каркас репозитория ✅ (этот сеанс)

Создан: README, RESEARCH, PLAN, CONSTRAINTS, LICENSES/NOTICE, .gitignore,
scripts/serve.js (стат-сервер с COOP/COEP), docs/BUILD.md. git init + коммит.

**Критерий выхода:** `node scripts/serve.js --selftest` показывает заголовки.

### S1. Конвейер сборки wasm

**Бриф.** Берём форк харнесса `paradust7/luanti-wasm` (MIT). Он фиксирует коммиты
всех зависимостей, включая форк движка `paradust7/luanti@webport` (база ≈5.18-dev).
Сборка только Linux: Docker (`FROM ubuntu:22.04`, `./build_all.sh`) или WSL2.
Публичных бинарников апстрим не публикует — артефакт получаем своим CI или локально.
Два варианта (см. вопрос пользователя Q-B):
- **CI (рекомендуется):** наш GitHub Actions job `ubuntu-latest`: docker-build харнесса
  + `build_www.sh`; артефакт — каталог `www/` (≈30–60 МБ: luanti.wasm + packs).
  Риск: линковка с INITIAL_MEMORY=2 ГБ может needing много RAM — при OOM снижать
  `-O2→-O1` или `INITIAL_MEMORY` через патч `build_luanti.sh`.
- **Локально:** WSL2 + `apt-get install build-essential cmake tclsh zstd gettext`,
  затем `./build_all.sh` (~40–90 мин; emsdk докачается сам).

Зафиксировать версии: пин коммита `paradust7/luanti@webport`, записать в `versions.lock`.

**Задачи:**
1. Завести наш форк/клон харнесса (после появления GitHub-репо) или положить клон
   в `vendor/luanti-wasm` (если decided локально).
2. Наш workflow `.github/workflows/build.yml`: docker build → артефакт `www/` (или
   `actions/upload-artifact` из plain-шагов без docker, если быстрее).
3. `scripts/get-build.ps1`: скачивание артефакта CI в `www/` (требует `gh auth`).
4. Запись `versions.lock` (sha харнесса, sha webport-форка, дата).

**Проверка:** артефакт содержит `www/<uuid>/luanti.wasm`, `www/<uuid>/packs/base.pack`,
`www/.htaccess`.

**Критерий выхода:** повторяемая сборка ≤2 часов, артефакт кладётся в `www/` без ручных
действий.

### S2. Локальный запуск ванили (врата качества) ⛔

**Бриф.** Статика отдаётся `scripts/serve.js` (уже есть): он ставит
`Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`,
`COEP-Credentialless`-исключения не нужны (всё same-origin). В консоли браузера
обязательно `crossOriginIsolated === true`. Порт по умолчанию 8484.

**Задачи:**
1. Открыть `http://127.0.0.1:8484/` в Chrome/Edge/FF, дождаться прогрева wasm.
2. Выбрать язык «Русский», создать мир (Minetest Game из ContentDB или ванильный devtest),
   поиграть 5 минут, обновить страницу → мир должен остаться (OPFS).
3. Снять замеры: время загрузки, FPS (F5), потребление RAM вкладкой.
4. Заложить `docs/VERIFY-S2.md` с результатами (скриншоты не нужны, цифры — да).

**Критерий выхода:** ванильный Luanti в браузере: старт, русский UI, мир переживает
рестарт вкладки. **Это блокирующий гейт.**

### S3. Оболочка RusCraft (бренд + русский лаунчер)

**Бриф.** Патчим статическую оболочку харнесса (`static/index.html`, строки в
`static/launcher.js`): заголовок/Title → «RusCraft», панель настроек, кнопки
«Launch/Exit/Show Console», выбор прокси, форма сервера — всё по-русски. Дефолт
`language = ru` через `setConf` (overrideConf уже поддержан). Логотип/иконка RusCraft,
цвета ближе к Luanti-палитре (тёмный фон, зелёный акцент). Не ломать `?lang=`,
invite-ссылки и server-only режим.

**Задачи:**
1. Наш оверлей `overlay/static/` вместо копий апстрима (поддержать `%__RELEASE_UUID__%`).
2. Русский словарь строк лаунчера (константный, без фреймворков).
3. `<title>`, favicon, мета-описание, «Об игре» (атрибуция Luanti + лицензия).
4. Тёмная тема в стиле оригинала; проверка контрастности WCAG AA.

**Проверка:** на собранном `www/` — все видимые элементы оболочки по-русски, бренд
RusCraft, `?lang=en` возвращает англ. язык игры, isolate-заголовки не тронуты.

**Критерий выхода:** игрок не встречает английских строк в оболочке и UI игры.

### S4. Игровой пак по умолчанию (офлайн-режим)

**Бриф.** Игру не качаем из ContentDB при первом запуске: собираем в CI отдельный
дата-пак (`minetestgame.pack` и/или `voxelibre.pack`, выбор — Q-A) и прописываем
автоустановку в `deploy.sh`/launcher-конфиге. Паки — обычные tar.zst по схеме харнесса
(`.packs/<name>.ver|.files`). Минус вес: VoxeLibre заметно тяжелее MTG (медиа-ассеты),
для веба это +N МБ — оценить на S2.

**Задачи:**
1. CI: скачать игру из ContentDB-архива или git-тега (пин), упаковать в `.pack`.
2. Прописать пресет конфига: `language=ru`, выбранная игра, `viewing_range` под
   веб-производительность (старт 100–128), отключение update-checker.
3. Скрыть/оставить ContentDB-менеджер (решение Q-A.2).
4. Проверка лицензий в `docs/LICENSES.md` (джоб-пак + медиа).

**Проверка:** первый запуск с чистым OPFS → мир выбранной игры создаётся без сети
(кроме CA-пака), интерфейс «Русский», FPS ≥ 30 на дефолтных настройках.

**Критерий выхода:** RusCraft стартует сразу в свою игру, одним экраном «Играть».

### S5. Внутриигровой русский и брендинг

**Бриф.** Переводы движка уже в пачке (ENABLE_GETTEXT=TRUE, po/ru). Проверяем:
главное меню, настройки, formspecы выбранной игры. Игровые моды переводит их автор —
у MTG ru-перевод хороший; у VoxeLibre частичный (апстрим Weblate, можно пуллы).
Бренд: title окна через `window_title = RusCraft` (setting), меню-заголовок/текстуры
через оверлей-пак `textures/` (меню Luanti берёт текстуры `menu_*.png`).

**Задачи:**
1. Инвентаризация untranslated-строк (скриншоты меню по шагам) — фиксы патчем
   `.po` или через `ruscraft-overrides` текстур-пак.
2. Кириллический шрифт: дефолтный DejaVuSans покрывает — проверить только.
3. `window_title`, «Об игре» экран, ссылки (репо, luanti.org).

**Проверка:** grep собранных `.mo`/скриншоты — ноль англ. строк в критических экранах
(создание мира, настройки, инвентарь выбранной игры).

**Критерий выхода:** скриншоты всех ключевых экранов — полностью русские.

### S6. Сетевая игра (мультиплеер)

**Бриф.** Браузерный Luanti ходит в сеть только через WSS-прокси (webshims emsocket).
Варианты: (а) публичные dustlabs — `eu1` (Франкфурт) дефолтом; (б) self-hosted
`lwproxy` (Rust, MIT) у нас на хостинге — нужен TLS-домен + nginx ws-Upgrade;
(в) режим «сервер в браузере» + invite-ссылка (уже в харнессе) — годится для игры
с друзьями без своего сервера. Подключение из десктопного Luanti к браузерному
серверу тоже работает через прокси.

**Задачи:**
1. Дефолт прокси — eu1 (или свой, Q-C).
2. Если self-host: `proxy/docker-compose.yml` + nginx-сниппет + healthcheck;
   лимиты/очереди; метрики подключений.
3. Инструкция «как позвать друга» (русский текст) + проверка invite-ссылок.
4. Тест: браузер ↔ десктоп 2 клиента на публичном тест-сервере Luanti.

**Проверка:** два браузера (или браузер+десктоп) в одном мире через прокси; пинг,
рассоединение, рестарт сервера.

**Критерий выхода:** мультиплеер работает как минимум в сценарии (в)+(а), задокументирован.

### S7. Хостинг и доставка

**Бриф.** Статика с заголовками. `www/.htaccess` апстрима — эталон заголовков
(COOP/COEP, immutable-кэш по uuid, MIME для wasm). Для nginx — наш конфиг в
`deploy/nginx.conf`. Кэширование: `/www/<uuid>/**` — immutable forever; `index.html` —
no-cache. Отдельно: размер при первом визите (wasm + base.pack), догревание кэша.
Домен/хостинг — зона ответственности человека (Q-D).

**Задачи:** 1) nginx/Caddy-конфиг; 2) проверка на реальном стенде (https обязателен —
OPFS/SharedArrayBuffer требуют secure context); 3) CI: публикация артефакта на
хостинг по тегу; 4) бэкап-политики нет (миры живут у игрока в OPFS — предупредить в UI).

**Критерий выхода:** по HTTPS-URL играется с нуля в приватном окне.

### S8. Производительность и слабые устройства

**Бриф.** Профили: desktop-strong (2 ГБ), desktop-weak (INITIAL_MEMORY=1 ГБ,
viewing_range 64), mobile-эксперимент (тач: у Luanti есть touch-режим Android-сборки;
для wasm — исследования на S2/S8, риск). Измерения на S2-сценариях.

**Критерий выхода:** профиль «слабый ПК» собирается и играет ≥20 FPS; мобильный
статус зафиксирован (да/нет/частично) в README.

## Протокол мутации плана

- Новый шаг: добавить с ID `Sx.y`, вписать в граф, отметить здесь и в README-таблице.
- Пропуск шага: только с явного согласия человека, запись «Пропущено: причина» ниже шага.
- Ветка апстрима webport отстанет >30 дней — вставить шаг S1.x «ребейз webport» и
  повторить S2-гейт.
